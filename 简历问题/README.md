## 11. 问题 + 高分示范回答（可背诵版）

> 结构统一：结论 -> 原理 -> 你做法 -> 指标 -> 边界。建议每题控制在 40~70 秒。

### 11.1 项目与系统

**Q1：为什么做 Agent + RAG，不直接纯大模型回答？**

**A（示范）**
结论：因为电商场景对正确性和可追溯性要求高，纯 LLM容易幻觉，Agent + RAG 更可控。
原理：RAG 先检索再生成，用外部知识约束回答；Agent 通过工具调用把“说”变成“做”，可闭环执行订单和退款。
我的做法：我把问题先做意图分类，咨询类走 RAG，交易类走 Function Calling，复杂或低置信度问题转人工。
指标：核心看 FCR、转人工率、工具成功率和 P95 延迟。
边界：冷启动知识库质量不足时效果不稳，所以我会补充重排和灰度评估。

**Q2：线上延迟突然升高你怎么处理？**

**A（示范）**
结论：先止血，再定位，再复盘。
原理：延迟可能来自检索、模型推理、外部工具或网络，必须链路化拆分。
我的做法：先降级到短上下文和小模型，关闭非关键工具；同时看分布式 tracing，把耗时拆到 embedding、vector search、LLM、DB。
指标：先把 P95 拉回 SLA，再看错误率和转人工率是否恶化。
边界：如果上游 LLM 不稳定，要启用多模型路由和熔断，避免单点依赖。

**Q3：如何减少“过度转人工”？**

**A（示范）**
结论：不能只靠单一置信度阈值，要加澄清问题和多特征判定。
原理：低置信度不一定不可答，可能只是用户表达不完整。
我的做法：我会先做一次澄清提问，再结合召回分数、历史会话一致性、工具可执行性打综合分，分层转人工。
指标：关注智能解决率提升的同时，监控投诉率不能上升。
边界：高风险业务（退款、投诉）仍应保守，优先可解释和安全。

### 11.2 RAG 深挖

**Q4：召回命中但回答错误，通常哪里出问题？**

**A（示范）**
结论：最常见是“检索相关但不充分”或“生成阶段引用错证据”。
原理：RAG 错误分三层：召回错、重排错、生成错。
我的做法：我会先做 evidence trace，检查模型是否引用了 top 文档；若未引用，强化引用约束；若引用后仍错，优化 chunk 切分和重排模型。
指标：看 groundedness（答案-证据一致性）和人工抽检准确率。
边界：对时效性强的知识，必须加更新时间权重和失效策略。

**Q5：Top-k 为什么不能固定？**

**A（示范）**
结论：固定 Top-k 在“简单问句”和“复杂问句”上都会有损失，动态策略更稳。
原理：简单问题过多文档会引噪声，复杂问题文档不足会漏信息。
我的做法：按问题长度、实体数量、历史失败率动态调整 k，并设置上限避免上下文爆炸。
指标：准确率和延迟通常能同时改善。
边界：动态策略要配离线回放，不然容易过拟合到某批数据。

### 11.3 Transformer / 注意力

**Q6：为什么 attention 要除以 sqrt(d_k)？**

**A（示范）**
结论：防止点积随维度变大导致 softmax 饱和，梯度变小。
原理：q·k 的方差随 d_k 增大，缩放后分布更稳定，训练更容易收敛。
我的做法：实现注意力时固定使用 scale，并配合 fp16 的数值稳定处理（减 max）。
指标：训练曲线更平滑，loss 抖动更小。
边界：极长序列时还要结合 mask 和 kernel 优化，不是只靠缩放。

**Q7：Pre-LN 为什么更稳定？**

**A（示范）**
结论：Pre-LN 残差路径更顺畅，深层训练更不容易梯度消失。
原理：归一化放在子层前，能让输入分布更稳定，优化器更好工作。
我的做法：工程里优先 Pre-LN，尤其是层数较深或数据噪声较大时。
指标：同等超参下收敛更稳，爆梯度更少。
边界：Post-LN 在部分设置下表达力可能更强，要结合任务验证。

**Q8：为什么 KV Cache 不缓存 Q？**

**A（示范）**
结论：因为 Q 只和当前 token 相关，每步都会变，没缓存价值。
原理：自回归解码中历史 K、V 会反复参与计算，而历史 Q 不会被复用。
我的做法：缓存层按 batch、layer、head 存 K/V，并做长度增长管理。
指标：解码复杂度从每步重算全序列降到增量计算，吞吐明显提升。
边界：缓存会增显存，长上下文需要分页或分块策略。

### 11.4 LoRA / 训练与对齐

**Q9：LoRA 为什么有效？**

**A（示范）**
结论：任务增量通常在低秩子空间中，低秩更新能以小参数量逼近全参效果。
原理：把权重增量分解为 A*B，冻结原权重，只训练低秩矩阵。
我的做法：优先在 attention 投影层注入 LoRA，按任务复杂度调 rank。
指标：显存和训练成本显著下降，效果接近全参。
边界：跨领域跨度很大时，低秩容量可能不够。

**Q10：PPO 和 DPO 的核心差别？**

**A（示范）**
结论：PPO 是在线 RL，复杂但灵活；DPO 是离线偏好优化，更简洁稳定。
原理：PPO 需要奖励模型和采样闭环；DPO 直接在偏好对上优化策略相对概率。
我的做法：数据充足、迭代周期紧时优先 DPO；需要细粒度行为控制时考虑 PPO。
指标：DPO 工程复杂度低，上线更快；PPO 在特定目标上可更精细。
边界：DPO 很依赖偏好数据质量，脏数据会直接带偏模型。

**Q11：为什么 RLHF 要加 KL 约束？**

**A（示范）**
结论：防止策略模型偏离参考模型过快，避免语言能力退化。
原理：奖励最大化会诱导投机策略，KL 相当于“别跑太远”的正则。
我的做法：我会把 KL 系数做动态调节，按目标困惑度和回复质量平衡。
指标：可降低 reward hacking 风险，回答更自然稳定。
边界：KL 过大可能抑制优化，过小又容易发散。

### 11.5 八股高频快答

**Q12：熵、交叉熵、KL 的关系？**

**A（示范）**
结论：交叉熵 = 熵 + KL。
原理：H(p,q)=H(p)+D_KL(p||q)，训练时最小化交叉熵等价于让 q 逼近 p。
我的做法：分类和语言建模都用交叉熵，并关注 label 噪声影响。
边界：类别极不平衡时要配重加权或 focal 类方法。

**Q13：你如何防提示注入和越权调用？**

**A（示范）**
结论：安全要“模型外”做，不能只靠提示词。
原理：LLM 不是权限系统，所有高风险动作必须后端再校验。
我的做法：工具白名单、参数 schema 校验、用户权限二次校验、审计日志全量记录。
指标：看越权拦截率、误拦截率、高危操作告警数。
边界：仍需红队测试持续攻防，不是一劳永逸。

**Q14：你如何证明项目是你主导而非参与？**

**A（示范）**
结论：用“职责边界 + 关键决策 + 量化结果”三件事证明。
我的做法：我会明确说负责了哪些模块、做了哪些关键 trade-off、上线后指标提升多少。
补充：再给一个失败案例和复盘，可信度会更高。
