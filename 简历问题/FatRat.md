# 肥鼠鼠｜大模型算法岗深挖面试文档（面试官版）

> 目标：基于你在大模型/Agent/RAG/算法手撕方向的简历内容，构建一份“高覆盖、可追问、可实战演练”的面试题库。
> 使用方式：先按模块自测，再进行 30/45/60 分钟模拟。

---

## 0. 面试官评估维度（你需要对齐）

1. **项目真实性**：你是否真的主导过关键模块，还是只做过边缘工作。
2. **算法深度**：是否能把 Transformer、LoRA、PPO/DPO 从原理讲到实现细节。
3. **工程落地**：是否具备线上系统设计、稳定性治理、性能优化能力。
4. **结果导向**：是否能说出量化指标与业务价值，而不只讲“做了很多”。
5. **复盘能力**：是否能讲清失败案例、取舍逻辑与下一步优化。

## 10. 结合问题的详细回答（可直接背诵）

> 使用方法：优先掌握 P0（高频高压）问题；每题按“结论 -> 原理 -> 实战 -> 指标 -> 边界”输出。

### 10.1 P0 项目深挖题（建议 60s/题）

**Q1：为什么这个项目必须用 LLM，而不是规则系统？**
**答：**
- 结论：电商客服问题长尾明显、表达多样，纯规则覆盖成本高，LLM 具备更强泛化能力。
- 原理：规则系统擅长确定性流程，LLM 擅长语义理解与意图归纳；二者结合才能兼顾稳定与智能。
- 实战：我采用“意图识别 + RAG + 工具调用”三段式，咨询类走知识检索，交易类走 API 执行。
- 指标：通常重点看首问解决率（FCR）、转人工率、工具成功率、P95 延迟。
- 边界：高风险动作不能仅靠模型，需要后端权限校验和人工兜底。

**Q2：你在项目中的不可替代贡献是什么？**
**答：**
- 结论：我主导了核心链路的架构落地与质量闭环，而非只做单点功能。
- 原理：LLM 项目成败不只在模型效果，还取决于检索质量、工具稳定性、线上可观测性。
- 实战：我负责从会话入口到回答输出的全链路设计，重点解决“误召回、工具失败、过度转人工”。
- 指标：可用智能率、转人工率下降、P95 稳定性提升来证明贡献。
- 边界：如果缺少业务数据治理，模型上限会受限，需要持续建设标注和评测集。

**Q3：Function Calling 如何做安全控制？**
**答：**
- 结论：安全必须“模型外”保证，不能信任模型自觉。
- 原理：模型可被提示注入影响，因此执行层必须做白名单、参数 Schema、权限二次校验。
- 实战：我会把工具声明严格结构化，执行前做用户身份和资源归属校验，执行后记录审计日志。
- 指标：关注越权拦截率、误拦截率、高风险调用告警数。
- 边界：仍需定期红队测试，不同提示注入手法要持续更新防护策略。

**Q4：RAG 命中文档但答案错，怎么排查？**
**答：**
- 结论：按“召回 -> 重排 -> 生成引用”分层定位，避免盲目调参。
- 原理：答案错误不等于召回错误，可能是重排顺序不佳或生成阶段未正确引用证据。
- 实战：先检查 top-k 文档相关性，再看模型是否引用 top 证据；必要时加引用约束与 rerank。
- 指标：看 groundedness（答案-证据一致性）、人工抽检准确率、幻觉率。
- 边界：时效性强场景必须引入文档新鲜度权重，否则旧知识会污染输出。

**Q5：如何降低过度转人工？**
**答：**
- 结论：不能单阈值硬切，需要“澄清提问 + 多特征打分”。
- 原理：很多低置信度来自用户信息不完整，而不是系统无能力回答。
- 实战：我会先自动追问补全关键信息，再结合召回分、工具可执行性、历史轮次一致性综合判定。
- 指标：目标是提升智能解决率，同时保持投诉率不升高。
- 边界：退款、投诉等高风险意图仍应保守，优先安全与可追溯。

### 10.2 P0 算法八股题（建议 45~60s/题）

**Q6：Attention 为什么除以 sqrt(d_k)？**
**答：**
- 结论：防止点积随维度增大导致 softmax 饱和、梯度变小。
- 原理：q·k 的方差与 d_k 相关，缩放后 logits 分布更稳定，有利于训练。
- 实战：实现时我固定 scale，并配合减去 max 的 softmax 稳定写法。
- 指标：训练曲线抖动更小，收敛更平滑。
- 边界：超长序列场景还需配合高效注意力或分块策略。

**Q7：Pre-LN 与 Post-LN 差异？**
**答：**
- 结论：Pre-LN 训练更稳，Post-LN 在部分配置可能表达更强但更难训。
- 原理：Pre-LN 让残差路径更通畅，深层网络梯度传播更友好。
- 实战：工程上我优先 Pre-LN，特别是层数较深、数据噪声较大时。
- 指标：通常表现为训练更稳定、爆梯度概率更低。
- 边界：具体选型仍要结合任务和模型规模做对比实验。

**Q8：KV Cache 为什么只缓存 K/V？**
**答：**
- 结论：历史 K/V 会被反复复用，历史 Q 不会复用，缓存 Q 价值低。
- 原理：自回归解码每一步只新增一个 token 的 Q，但要与所有历史 K/V 计算注意力。
- 实战：我按 layer/head/batch 维护 K/V 缓存，并处理长度增长与显存管理。
- 指标：吞吐提升明显，单 token 解码延迟下降。
- 边界：长上下文下显存压力上升，需要分页或窗口化缓存。

**Q9：LoRA 为什么有效？**
**答：**
- 结论：任务迁移的有效更新通常位于低秩子空间，低秩分解可近似全参更新。
- 原理：冻结原权重，仅训练 A、B 两个低秩矩阵，显著减少可训练参数。
- 实战：优先在 attention 投影层加 LoRA，按任务复杂度调 rank 和 alpha。
- 指标：显存占用和训练成本下降，效果接近全参微调。
- 边界：跨领域跨度大时低秩容量不足，可能需提高 rank 或切全参。

**Q10：PPO 与 DPO 如何取舍？**
**答：**
- 结论：DPO 工程更简洁稳定，PPO 更灵活但复杂度更高。
- 原理：PPO 依赖在线采样与奖励模型；DPO 直接在偏好对上优化策略相对偏好。
- 实战：迭代周期紧、数据质量较好时优先 DPO；需细粒度行为控制时考虑 PPO。
- 指标：DPO 上线速度更快；PPO 在特定 reward 目标下上限更高。
- 边界：DPO 非常依赖偏好数据质量，脏数据会直接误导优化方向。

### 10.3 P0 工程生产化题（建议 60s/题）

**Q11：如何把 P95 延迟压到目标线内？**
**答：**
- 结论：先分解链路，再按“高收益低风险”优先级优化。
- 原理：延迟常由检索、模型推理、外部 API 三段组成，必须逐段定位。
- 实战：我会优先做缓存命中优化、上下文裁剪、模型路由分层；并设置超时熔断与降级。
- 指标：看 P50/P95/P99、错误率、转人工率联动变化。
- 边界：过度降级会伤害回答质量，要通过 A/B 保证体验不退化。

**Q12：如何设计可观测性？**
**答：**
- 结论：必须同时建设日志、指标、链路追踪三件套。
- 原理：日志用于定位个案，指标用于监控趋势，追踪用于定位瓶颈环节。
- 实战：我会为每次会话打 trace_id，串联用户输入、检索结果、模型输出、工具调用。
- 指标：重点监控请求量、延迟分位、工具失败率、幻觉率、转人工率。
- 边界：日志要做脱敏和分级留存，避免隐私泄露与存储失控。

**Q13：线上故障如何复盘？**
**答：**
- 结论：复盘核心是“可重复、可归因、可预防”。
- 原理：事故治理不是写总结，而是补齐监控、流程、预案和自动化校验。
- 实战：我按“现象 -> 时间线 -> 根因 -> 修复 -> 防再发”模板输出，并补压测和告警规则。
- 指标：看同类故障复发率、平均恢复时长（MTTR）、告警误报率。
- 边界：若没有演练机制，文档化复盘很难真正落地。

### 10.4 行为面高分答法（建议 45s/题）

**Q14：讲一个失败案例。**
**答：**
- 结论：我会选“有业务损失但可复现可改进”的失败，不回避责任。
- 原理：面试官看的是问题处理能力，不是零失误神话。
- 实战：说明当时误判原因、止损动作、后续机制改进（如评测集/灰度/回滚开关）。
- 指标：给出修复前后差异，如故障时长下降、误触发率下降。
- 边界：承认当时认知不足，并说明后来如何系统补课。

**Q15：如何证明你是主导者？**
**答：**
- 结论：用“职责边界 + 关键决策 + 量化结果”三证合一。
- 原理：头衔不重要，交付闭环才是主导证据。
- 实战：讲 1 个你独立推进的关键改造，含背景、阻力、推进方式、结果。
- 指标：至少给 2 个硬指标和 1 个跨团队影响。
- 边界：明确哪些成果是团队共创，避免过度归因。

### 10.5 追问扩展卡（面试官常用）

**追问卡 A（项目真实性）**
- 主问：你说做了 RAG 优化，具体改了哪 3 个参数？
- 追问：每个参数对准确率和延迟影响分别是多少？
- 收束答法：先给改动点，再给对比实验结论，最后讲 trade-off。

**追问卡 B（算法深度）**
- 主问：你说懂 DPO，请写出核心优化目标。
- 追问：beta 变化对输出分布有何影响？
- 收束答法：先公式直觉，再工程含义，再给调参经验。

**追问卡 C（工程能力）**
- 主问：如果上游模型 API 波动，你如何保证服务可用？
- 追问：哪些请求会降级，哪些必须失败快返？
- 收束答法：按优先级给降级矩阵，强调 SLA 与业务风险分级。

### 10.6 指标话术库（避免“空话”）

- 准确率：`离线评测准确率从 A 提升到 B，线上抽检一致性提升 C%`。
- 延迟：`P95 从 X ms 降到 Y ms，峰值时段超时率下降 Z%`。
- 成本：`平均每次会话 token 成本下降 C%，缓存命中率提升 D%`。
- 稳定性：`工具调用失败率从 E% 降到 F%，MTTR 缩短 G%`。
- 业务：`转人工率下降 H%，用户满意度提升 I%`。

> 建议：把 A/B/C... 替换成你真实数据，至少准备 8~10 个“数字证据点”。
